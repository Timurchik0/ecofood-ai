# EcoFood AI — скрининг заявок пищевых предприятий

**Проблема.** Официальная статистика показывает рост пищевого производства, но детальных оперативных данных о потоках
пищевых отходов конкретных предприятий практически нет. Без этих данных нельзя понять, кому предлагать переработку,
и приходится звонить всем подряд.

**Решение.** Предприятия заполняют короткую анкету (Google-форма или форма в приложении). EcoFood AI автоматически
оценивает каждую заявку по прозрачным критериям, присваивает статус **HOT / WARM / COLD**, а AI объясняет менеджеру,
почему приоритет такой, и подсказывает следующий шаг. Всё собрано на дашборде с приоритетным списком и мини-CRM.

> На первом этапе используется экспертная rule-based модель скоринга. После накопления данных пороги и веса
> калибруются на фактическом поведении предприятий — прямо в настройках, без правки кода.

## Что умеет (MVP)

| Блок | Что делает |
|---|---|
| **Приём заявок** | Google-форма (через ссылку на таблицу) и своя форма `/apply` |
| **Скоринг** | 6 критериев, 100 баллов, HOT ≥ 75 · WARM 50–74 · COLD < 50. Свободный текст («1,5 тонны», «около 20 тыс.», «50 кг в день») разбирается автоматически |
| **Дашборд** | KPI, структура HOT/WARM/COLD, разрезы по виду деятельности, региону, типу отходов, динамика по дням, приоритетный список с фильтрами |
| **Карточка лида** | Расчёт баллов по каждому критерию, AI-заметка, CRM-статус (Новая → Контакт → Интервью → Пилот → Закрыта / Отказ), заметки менеджера |
| **AI (Claude)** | Объясняет приоритет, предлагает следующий шаг и вопросы для звонка, разбирает числа из свободного текста, когда парсер не справился |
| **Настройки** `/admin` | Пороги и веса скоринга с предпросмотром и пересчётом — **открыты без входа** (закрыть: `SETTINGS_LOCKED=1`). Под ключом администратора: контакты компаний, ссылка на таблицу, выгрузка CSV, демо-данные, AI-заметки |

## Модель скоринга

| Критерий (вопрос анкеты) | Вес | Как считаются баллы |
|---|---|---|
| Объём отходов, кг/мес (5) | 30 | до 100 — очень малый · 100–500 — малый · 500–2000 — средний · от 2000 — крупный |
| Готовность передавать переработчику (9) | 25 | Да — 100% · Зависит от условий — 48% · Нет — 0 |
| Регулярность вывоза (6) | 15 | ежедневно — 100% … по мере накопления — 20% |
| Интервью / пилот (11) | 15 | Да — 100% · Возможно — 47% · Нет — 0. Если в анкете нет отдельного вопроса, считается по наличию контакта (телефон / e-mail / @telegram) |
| Расходы на вывоз, сом/мес (8) | 10 | до 2 000 — низкие · 2 000–5 000 — средние · 5 000–10 000 — высокие · от 10 000 — очень высокие |
| Текущий способ вывоза (7) | 5 | вместе с коммунальными (нет решения) — 100%, другим лицам — 60%, спецорганизация — 40%, перерабатывают сами — 0 |

* **Все пороги, границы и веса — в настройках** (таблица `settings` в БД, страница `/admin`). После сохранения баллы всех
  заявок пересчитываются из сохранённых ответов, **сами ответы предприятий не меняются**. Есть предпросмотр: «сколько
  заявок сменит статус при новых настройках».
* **Правило отказа:** ответ «Нет» на передачу отходов → лид автоматически COLD (иначе такое предприятие могло бы набрать
  до 75 баллов за счёт объёма и расходов). Отключается в настройках.
* Тип отходов, регион и вид деятельности в баллах не участвуют — это фильтры и срезы дашборда.
* Доли внутри критерия (например, 48% за «Зависит от условий») — экспертные константы в `src/lib/scoring.ts`.

## Как работает AI и почему это не «обёртка над чат-ботом»

Балл и статус считают **правила** — они воспроизводимы и объяснимы. AI встроен в конвейер заявки и делает то, что правилами
не сделать:

1. **Объясняет** приоритет простым языком, опираясь на баллы по критериям.
2. **Подсказывает действие**: что предложить, по какому каналу, какие вопросы задать на звонке (в том числе когда контакта нет).
3. **Разбирает свободный текст**, который парсер не распознал («полтонны», «около 5 тысяч»), и подставляет число в скоринг
   (с пометкой «разобрано AI — проверьте»).

Защита и экономия: ответы публичной формы передаются модели как данные (не инструкции); сами контакты в API **не отправляются**;
заметка создаётся один раз при поступлении заявки и хранится в БД — открытый демо-дашборд не тратит запросы на просмотры.
Без `ANTHROPIC_API_KEY` приложение работает полностью: заметки строятся по шаблону на тех же баллах (помечаются как шаблонные).

## Архитектура

```
 Google-форма ──► Google-таблица ──► ссылка на CSV ──► синхронизация (раз в минуту при открытом дашборде)
                                    └─ (необязательно) Apps Script ──► POST /api/intake (x-intake-secret)
 Форма /apply  ───────────────────────────────────────────► Server Action
                                    │
                                    ▼
              разбор колонок по ключевым словам → parse.ts (кг, сом, контакт)
                                    │
                                    ▼
                         scoring.ts (конфиг из БД) ──► score, HOT/WARM/COLD, разбивка по критериям
                                    │
                         Postgres (Neon) ◄──────────── ai.ts (Claude): заметка + разбор текста, после ответа клиенту
                                    │
                                    ▼
                  Дашборд · карточка лида · CRM-статусы · /admin
```

* **Next.js 16** (App Router, Server Components, Server Actions) + TypeScript + Tailwind v4 — один проект на Vercel.
* **Postgres**: Neon на Vercel (`pg`); локально без настройки — встроенный PGlite. Таблицы создаются автоматически.
* **Идемпотентность:** заявки из Google дедуплицируются по отметке времени, повторный импорт безопасен.
* **Колонки сопоставляются по ключевым словам** в названии вопроса — мелкие правки формулировок в форме ничего не ломают.
* **Открытое демо:** дашборд, анкета и настройки скоринга без входа; контакты компаний маскируются (`0555 *** *56`), а контакты, выгрузка, импорт и подключение таблицы доступны только админу по `ADMIN_KEY`.

## Запуск локально

```bash
npm install
npm run dev          # http://localhost:3000, база PGlite создаётся сама (папка .data)
npm test             # 74 теста: парсер текста, скоринг, сопоставление колонок, CSV
```

Локально (без `ADMIN_KEY`) вы автоматически администратор: на `/admin` можно загрузить демо-данные.

## Деплой на Vercel (10 минут)

1. Залить репозиторий на GitHub и импортировать в Vercel (**Add New → Project**).
2. **Storage → Create → Neon (Postgres)** → привязать к проекту. Появится `DATABASE_URL`.
3. **Settings → Environment Variables:** `ADMIN_KEY`, `INTAKE_SECRET` (любые длинные строки), по желанию `ANTHROPIC_API_KEY`.
4. **Redeploy.** Открыть `/admin`, войти по `ADMIN_KEY`, подключить таблицу или загрузить демо-данные.
5. **Утром 10 октября откройте ссылку заранее:** бесплатная база Neon «засыпает» без трафика, первый запрос будет медленнее.

Переменные окружения — в [.env.example](.env.example).

## Подключение Google-формы

Таблица ответов должна быть привязана к форме (вкладка «Ответы» → «Связать с Таблицами»). Дальше:

1. Откройте таблицу по ссылке («Все, у кого есть ссылка — читатель») или опубликуйте её как CSV (Файл → Поделиться → Опубликовать в Интернете).
2. Вставьте ссылку на `/admin` в блок «Google-таблица с ответами» (или задайте переменную `GOOGLE_SHEET_URL`).

Накопленные ответы загрузятся сразу, новые подтягиваются каждую минуту, пока открыт дашборд. Повторная загрузка безопасна: дубликаты
определяются по отметке времени. *В таблице контакты компаний, не передавайте ссылку посторонним.*

Необязательная альтернатива — закрытая отправка из самой таблицы: `google-apps-script/Code.gs` (в скрипте подставьте адрес
`https://<ваш-домен>/api/intake` и значение `INTAKE_SECRET`; в Apps Script выполните `sendAll`, затем `setup`).

## Что не входит в MVP (следующие шаги)

* Авторизация сотрудников (сейчас — один ключ администратора; в открытом демо контакты скрыты).
* Калибровка модели на реальных данных (пилот → какие лиды реально дошли до интервью/пилота → подбор весов).
* Уведомления менеджеру (Telegram/WhatsApp) о новом HOT-лиде.
* Рейт-лимит на Redis вместо памяти инстанса, повторный опрос предприятий.

## Структура

```

src/lib/intake.ts     сопоставление колонок формы → поля, запись заявки
src/lib/ai.ts         Claude: заметка менеджеру + разбор текста; шаблон без ключа
src/lib/sheet.ts      синхронизация с Google-таблицей (CSV)
src/lib/leads.ts      работа с БД: заявки, статистика, настройки, пересчёт
src/app/              страницы: дашборд, /leads/[id], /apply, /admin, /api/intake
google-apps-script/   скрипт для таблицы ответов
```
